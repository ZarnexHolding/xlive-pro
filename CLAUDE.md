# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing/portfolio site for **XLIVE Production**, a Riyadh-based event production & experience-engineering company (part of Zarnex Holding). Multi-page React SPA. The goal is a premium, trust-building site aimed at government entities, giga-projects, luxury brands, and international/Dubai agencies delivering into Saudi Arabia.

> ⚠️ `README.md` is the **outdated pre-rebuild scaffold** (it still says React 18, Syne/DM Sans, coral `#E84530`, gsap/swiper, `src/sections/`). Ignore it — this file reflects the current codebase.

## Commands

```bash
npm install
npm run dev        # Vite dev server (http://localhost:5173)
npm run build      # production build -> dist/ (vite build + scripts/prerender.mjs static HTML per route)
npm run build:spa  # client build only, no prerender (debugging)
npm run preview    # serve the production build (use trailing-slash URLs, e.g. /about/, to hit the prerendered files locally)
npx vercel dev     # run the site WITH the /api serverless function locally (see Contact backend)
python scripts/images.py   # regenerate WebP variants after adding a JPG to public/images
```

There is **no test or lint script** configured (package.json has only dev/build/preview). The project is **JavaScript/JSX — no TypeScript** (despite `@types/react` being present).

## Tech stack

React 19 + Vite 5 · Tailwind CSS 3 · **GSAP 3 + ScrollTrigger (all animation, `@gsap/react` `useGSAP`)** · Lenis (smooth scroll, driven by the GSAP ticker) · react-router-dom 7 · React 19 native `<title>`/`<meta>` head tags (no helmet) · react-icons · Resend (contact email, serverless only). **Framer Motion and react-helmet-async were removed (Sept 2026)**; do not reintroduce them. Deploys to **Vercel**.

**Build = static prerender.** `npm run build` runs `vite build` and then `scripts/prerender.mjs`, which SSR-renders every public route (`/`, `/work`, `/work/<slug>`, `/partners`, `/about`; list in `src/entry-server.jsx`) into complete HTML (`dist/about.html` + `dist/about/index.html`, etc.). `src/main.jsx` hydrates when the root already has content. Crawlers get full HTML + per-route meta without JS; first paint no longer waits for the JS bundle. `vercel.json` sets `cleanUrls` so `/about` serves `about.html`; unknown paths still fall back to the SPA `index.html` rewrite.

The Vite app lives at the **repository root** — `src/`, `public/`, `api/`, `index.html`, `vite.config.js`, `package.json`, `vercel.json` are all at the top level (the app was flattened up from an earlier `frontend/` subfolder, so ignore any lingering `frontend/…` path references).

## Architecture

**Routing & shell** — `src/App.jsx` defines routes. `SiteLayout` (Navbar + `<Outlet>` + Footer) wraps `/`, `/work`, `/work/:slug`, `/partners`, `/about`; it also mounts `useLenis()` and a `ScrollToTop`. `/styleguide` is standalone. Home is eager; every other page is **`React.lazy` code-split**. Entry is `src/main.jsx` (BrowserRouter + HelmetProvider + Analytics).

**Pages** (`src/pages/`) — `Home` composes section components in order: `Hero → ProofBand → WhoWeAre → Capabilities → Work → Fabrication → Industries → PartnersTeaser → Contact`. `Work` (index) + `CaseStudy` (`/work/:slug`, uses `getProject`, redirects to `/work` if slug not found), `Partners` (the conversion page), `About`, `StyleGuide` (living design-system reference).

**Components** — `components/sections/*` are page sections; `components/ui/*` are reusable primitives (`Button`, `ProjectCard`, `Img` (responsive WebP `<picture>` with width/height), `LazyVideo` (poster-first, source attached after load/idle, pauses off-screen), `XSymbol`/`XMotif`, `BackButton`); `components/Seo.jsx` (React 19 head tags); `components/animations/Reveal.jsx` exports `Reveal`/`RevealGroup`/`RevealItem` (GSAP ScrollTrigger, same API as before) and `SplitWords.jsx` (masked word reveal, `.split-line`/`.split-word`). Hooks: `useLenis` (+ `getLenis()`, `scrollToTarget()`), `useMagnetic` (magnetic CTA hover). `src/lib/gsap.js` is the single GSAP entry (registers ScrollTrigger + useGSAP, exports `MOTION_OK`/`DESKTOP` media queries).

**Content lives in `src/data/`, not in components** — `company.js` (nav, metrics, clients, contact/address), `capabilities.js`, `projects.js` (+ case-study fields + `getProject`), `fabrication.js`, `industries.js`, `partners.js`, `about.js`. Change copy here. **All content must stay real** — sourced from XLIVE's actual brand/profile/projects documents. Do not invent projects, metrics, or client names.

## Design system (this is the important part)

**Single source of truth = `tailwind.config.js`.** The same values are mirrored as CSS custom properties in `src/styles/globals.css` `:root` (for canvas/SVG/inline gradients) — **keep the two in sync.**

- **Color** — near-black cool canvas `ink.{950..500}`; **`electric` `#2A1AAE`** is the structural brand color (grounds, gradients, glow); **`acid` `#73F83E`** is the *single* high-voltage accent — **use sparingly** (CTAs, ticks, "live" signals); `vivid`/`olive` support; text `fg`/`fg-muted`/`fg-dim`; hairlines `line`/`line-soft`/`line-strong`.
- **Type** — display = **Archivo variable** (`font-display`, Google Fonts with the `wdth` axis; `.font-wide` = 125% width for hero/CTA statements, `.font-semi-wide` = 112% for section headings; Helvetica Neue is the fallback), body = `Hanken Grotesk` (`font-body`), technical labels = `JetBrains Mono` (`font-mono`; the `.index` class for "01"/meta labels). Fonts load non-blocking in `index.html` (preload + `media="print"` swap). Use the fluid `fontSize` tokens: `display-2xl`, `display-xl`, `display-lg`, `heading`, `subhead`, `body-lg`, `label`. Display headings are bold, tight (`tracking-tightest`), often uppercase. Keep text at 12px or larger (`text-xs`), never `text-[11px]` (Lighthouse legibility). `fg-dim` is `#767D95` (passes AA on the canvas); do not darken it.
- **Reusable classes** (`globals.css` `@layer components`/`utilities`): `.shell` (max-width page gutter), `.eyebrow` (label with acid tick), `.index` (mono meta label), `.btn-primary`/`.btn-outline` (pill), `.card`, `.bg-grid`, `.bg-glow-blue`, `.mask-x` (marquee edge fade), `.grain` (hero film grain), `.gpu`. Motif SVG via `XSymbol`/`XMotif`.
- **Motion** — GSAP + ScrollTrigger + Lenis. Rules: every animation lives inside `useGSAP(() => {…}, { scope })` so it is cleaned up on unmount; wrap motion in `gsap.matchMedia()` with `MOTION_OK` (reduced-motion users get static, fully visible content, so never hide content with CSS; let GSAP set the hidden start state); animate transforms/opacity only; pinned sections (`Hero`, `WhoWeAre` manifesto, `Capabilities` horizontal strip) are desktop-only where noted and use `anticipatePin: 1`. **Never let an intro timeline and a scroll-scrubbed timeline tween the same element** (the scrub captures the intro's start value; this once made the hero headline vanish). Use separate wrapper elements and `immediateRender: false` on scrubbed `fromTo`s.
- **Prerender hand-off** — `html.pre-hydrate` (set in `index.html`) hides only the intro-animated hero words and CTAs until `SiteLayout` removes it after hydration; everything else must paint from the static HTML (that is what makes first paint and LCP fast). If you add a new intro-animated element, add its selector to the `pre-hydrate` rule in `globals.css`, and keep the LCP text (hero sub-copy) static.

## Conventions & gotchas

- **Button variants**: never override a variant's color by appending a `className` (Tailwind precedence is source-order, not class-order — this once produced a black-on-black button). Add a new variant in `components/ui/Button.jsx` instead (e.g. `dark`).
- **Nav items** (`company.js` `nav`): items use **`href`** for in-page anchors (Home sections) or **`to`** for routes. `Navbar` and `Footer` branch on which is present; anchor clicks from a non-home route navigate home first, then scroll (via Lenis `getLenis()`).
- **Featured Work section** (`components/sections/Work.jsx`): the project matching `FEATURED_SLUG` (Saudi GP) gets a full-width cinematic block (main image + a 3-image strip from its `gallery` + its `scale` stats + the `challenge` line); the remaining projects fill a uniform grid driven by `LAYOUT` (desktop `[6|6] [4|4|4]`, tablet 2-up with the last card full-width; sized to `projects.length - 1`). Cards in a row share a width so their heights match (`ui/ProjectCard.jsx` sizes: `lg` = 16:10, `md` = 4:3). If you add/remove a project in `data/projects.js`, update `LAYOUT` (both the `md:` and `lg:` spans) so every row stays full (it falls back to the last entry so it won't crash), and keep the featured project's `gallery` at 3+ images. The `/work` index page (`pages/Work.jsx`) has its own `SIZES` array.
- **Home copy rules** (Sept 2026 redesign, keep them): home sections are a headline + at most one line + a visual, never bullet lists or explainer paragraphs (detail lives on `/work/:slug`, `/partners`, `/about`). **No em dashes or en dashes anywhere in the site: visible copy, code comments, log strings, the enquiry email templates and the JSON-LD in `index.html`** (swept clean on 13 Oct 2026; use a comma, period or colon instead, a hyphen for ranges such as `2023-2025`, and a middle dot for index labels such as `01 · Palette`). Check before committing with a Unicode-aware search (ripgrep, or Python counting `—`/`–`) across `src/`, `api/` and `index.html`. Do not use Git Bash `grep "[—–]"`: it matches raw UTF-8 bytes, so curly apostrophes (`’`) and arrows (`→`) produce false positives. Max ~1 eyebrow (`.eyebrow`) per 3 sections (only Contact keeps one). Never overlay tag pills on photos; project meta goes in the caption band (`ui/ProjectCard.jsx`).
- **Images**: JPGs in `public/images/` (real project photos extracted from source decks) plus generated WebP variants (`<name>.webp` up to 1600w, `<name>-800.webp`). Always render through `ui/Img.jsx` (`<picture>` + WebP srcset + width/height, `priority` for the LCP image) and add a new photo's dimensions to its `DIMS` map; run `python scripts/images.py` after adding a JPG.
- **Video**: `public/videos/hero-1080.mp4` (2.4 MB) / `hero-720.mp4` (1.1 MB, below 1024px) for the hero and `pitlane-720.mp4` (1.2 MB) for the Partners teaser, all encoded from the owner's clips in `../videos/` (h264, no audio, faststart). Posters `images/hero-poster.webp` (preloaded in `index.html`) and `pitlane-poster.webp`. Always go through `ui/LazyVideo.jsx` (poster `<img>` first, video source attached after `load` + idle, never under reduced-motion/save-data, paused off-screen). These clips are the owner's reference footage, not documented project photography: never caption them as a specific real event.
- **SEO**: per-route `<Seo>` renders React 19 `<title>`/`<meta>`/`<link rel=canonical>` (hoisted to `<head>`, swapped on route change) and the prerender writes them into each route's static HTML. `index.html` holds only site-wide bits (Organization JSON-LD, `og:site_name`) — do **not** add a static `<title>` or per-page meta there (duplicates). `public/robots.txt` + `public/sitemap.xml` list all routes. Lighthouse baseline after the Sept 2026 rework (production build, home): desktop 99 perf / 100 SEO / 96 a11y; mobile ~80 perf under throttling, TBT ~150 ms, CLS 0.

## Contact / enquiry backend

`POST /api/contact` is a **Vercel Serverless Function** — but a *thin adapter* only. It reads env → `buildConfig()` → hands the request to the runtime-agnostic core `api/_lib/enquiry.js` (`processEnquiry`). The backend is the **source of truth**; Gmail (Resend) and WhatsApp are notification channels. Full reference: [docs/ENQUIRY-SYSTEM.md](docs/ENQUIRY-SYSTEM.md).

Pipeline: validate + sanitize → honeypot (`website`) → per-IP rate-limit → idempotency (`submissionId`) → allocate Lead ID (`XL-2026-0001`) + **persist** → notify (admin email, team WhatsApp, customer WhatsApp ack on opt-in), each independent + status-tracked → return `{ leadId }`.

- **`api/_lib/` is the core** (not routed — the `_` prefix keeps Vercel from making endpoints): `config.js` (the ONLY place env is read — the deployment seam), `enquiry.js`, `validate.js`, `store.js` (Neon Postgres + in-memory fallback), `email.js`, `whatsapp.js` (mock + live adapters), `leadId.js`, `logger.js`. Other routes: `api/enquiries.js` (token-gated debug list), `api/webhooks/whatsapp.js` (GET verify + POST receive, no auto-reply).
- **Form** (`components/sections/Contact.jsx`) collects name, company, email, **phone**, project type, project, **`whatsappOptIn` checkbox**; sends a `submissionId` (UUID) for dedupe. Client + server validation both run; server is authoritative. Consent is optional — no opt-in just skips the customer WhatsApp ack.
- **Phone field** = `components/ui/CountryPhoneInput.jsx`, a custom searchable country-code picker (no dependency; dial codes in `data/countries.js`, default Saudi Arabia). The form composes the full **E.164** number (`+<dial><national digits>`) before POSTing as `phone`. To add/remove a country, edit `data/countries.js`.
- **Deploy source note**: production builds from **this folder, `xlive-web/`** (renamed from `website/` on 24 Sep 2026; git repo now `ZarnexHolding/xlive-pro` on GitHub, transferred from `mohdadnancode/xlive-production` by Oct 2026, → Vercel auto-deploy on push). The sibling `../claude/` folder is a **stale** workshop copy from September: it predates the premium rework and must never be copied over this folder. Work here only.
- **Database = Neon** (`@neondatabase/serverless`, HTTP driver). Set `DATABASE_URL`; schema auto-creates. No `DATABASE_URL` → in-memory fallback (works, but NOT durable across cold starts).
- **WhatsApp = MOCK for now** (no Meta creds yet). The mock adapter is used when `NOTIFICATIONS_MODE=test` (default), `WHATSAPP_MOCK=true`, or creds are missing — logs what it *would* send, nothing real goes out. Do NOT claim WhatsApp works until real Meta creds are set (`NOTIFICATIONS_MODE=live`) and tested. Official Meta Cloud API only — never web automation / unofficial libs.
- **Deployment-agnostic** (planned Cloudflare migration): core touches only `fetch` + `buildConfig(env)`, never `process.env` directly. Migrating = rewrite the 3 handlers in Cloudflare form + swap `node:crypto`→Web Crypto and `x-forwarded-for`→`cf-connecting-ip` in the webhook; core is unchanged. See the Cloudflare section in the doc.
- Env vars (all in `.env.example`): email `RESEND_API_KEY`/`CONTACT_TO`/`CONTACT_FROM`; `DATABASE_URL`; flags `NOTIFICATIONS_MODE`/`EMAIL_NOTIFICATIONS_ENABLED`/`TEAM_WHATSAPP_ENABLED`/`CUSTOMER_WHATSAPP_ENABLED`; `ADMIN_API_TOKEN`; `WHATSAPP_*`.
- **Env-var quoting gotcha**: in the **Vercel dashboard** the value box is literal — do **not** wrap values in quotes. A quoted `CONTACT_FROM` becomes an invalid sender → Resend **502**. Quotes belong only in a `.env` *file*. Editing env vars requires a **redeploy**.
- **`/api` does not run under `npm run dev`** — use `npx vercel dev` (with a local `.env`). `vercel.json` rewrites all non-`/api` routes to `index.html`.
